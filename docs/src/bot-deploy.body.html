Что нужно боту на сервере

Один процесс Python без базы данных. Всё состояние живёт в Pyrus. Ниже — с кем бот говорит, зачем, и что требуется, чтобы он работал на bot.ai.ind.studio.

01Из чего состоит

ЭлементГдеЗачем
Процесс ботасерверпринимает заявки из чата и Mini App, создаёт задачи в Pyrus, ведёт карточки в чате отдела, шлёт уведомления
.envсервер, рядом с кодом5 значений: токен бота, id чата отдела, логин и ключ Pyrus, адрес и ключ Supabase. В git не хранится
Pyrusоблакоединственное хранилище заявок — бот пишет и читает под служебным аккаунтом
Supabaseоблакотексты и картинки карточек тем; читается один раз при старте
Mini AppVercelостаётся как есть; свой ключ Pyrus, свои переменные

02Что нужно от сервера

  1. Python 3.12 — или Docker, образ соберу сам.
  2. Исходящий HTTPS к api.telegram.org, api.pyrus.com, *.supabase.co. Без прокси, либо прокси в переменной окружения.
  3. Автоперезапуск при падении и после ребута: systemd Restart=always или restart: always в compose.
  4. Доступ для развёртывания: SSH, либо ваш стандартный путь — CI или администратор.
  5. Место для .env: файл рядом с кодом или ваш secret-store.

03Запуск

git clone git@github.com:ind-studio/comp_design_bot.git
cd comp_design_bot
pip install -r requirements.txt
cp .env.example .env        # заполнить 5 значений
python -m bot.main

Работать должен один экземпляр: два процесса с одним токеном спорят за обновления Telegram. После переноса локальный экземпляр у Дария выключается.
